# 什么是RDMA 回环消息
 `RDMA` 回环消息，即 源和目的的`GID/LID`相同。
 注：一个`GID`，其实就对应接口的一个`IP`。如果一个接口上存在多个`IP`，那么就存在多个`GID`；

一个接口上多个`IP`对应的`GID`之间的通信，不能被视为回环消息，因为源和目的的`GID`不同， 消息还是会被RNIC给拆分，封装为包，经过上联交换机，再回来。

**RDMA本机和本机通信**意思是在**同一台物理主机上，两进程之间通过RDMA通信**。这是一个比较特殊但有用的场景，常见于开发、测试或某些容器场景。

## RDMA回环消息的特点
（1）源和目的的`GID/LID`相同
（2）消息不会被RNIC给拆分，封装为包，发到上联交换机。

# RDMA回环消息和以太网回环的区别
在以太网中，`sip`和`dip`相同的通信，则是软件协议栈处理的，数据包不会经过物理网络，也不会经过上联交换机，直接内核协议栈，就可以将包转发到目的进程。
但是在RDMA中，==`sgid`和`dgid`相同的通信，还是需要到RNIC硬件的，只不过没有经过上联交换机==，RNIC硬件(通过DMA的方式)就可以将消息转送到目的地。其实，在应用层的编程中，其实根本不需要区分是否为回环消息，通用编程即可。

# RDMA回环消息和非回环消息的区别
那么，回环消息和非回环消息有什么区别？  
在回环消息中，数据包不会被生成，也不会出现在端口的物理链路上，这会产生几个影响：

- 端口外的包嗅探器不会看到回环消息。
- 对于回环消息，端口计数器不会增加（字节数 + 数据包数）。
- RDMA设备可能会忽略路径属性（MTU、源路径位、静态速率）。SL可以使用——这依赖于具体实现。
- RDMA设备可能对处理回环消息进行了优化，因为它们不需要分割成数据包、创建头部、计算校验和并在接收时验证。

# 本机和本机通信是否使用RDMA回环消息
同一个机器上的不同进程之间（甚至是同一个进程的不同线程之间），进行大数据的拷贝。使用`memcpy`或者是`unix socket`当然很好，但是这个会消耗`CPU`的资源，通过`RDMA回环消息`来进行本机进程之间的通信，可以节约`CPU`干其他的事情。

# RDMA回环消息的dip可以是`127.0.0.1`吗？
RDMA本机和本机通信是在同一台物理主机上，两进程之间通过RDMA通信。
不能使用 `127.0.0.1`（localhost）进行 本机2个进程之间的 RDMA 通信。因为`127.0.0.1` 是回环接口（LO: loopback interface)的IP，它不绑定到任何实际的网络设备（如 RDMA 网卡，也叫 HCA）。

正确的做法：使用绑定到本机 RDMA 网卡的实际 IP 地址（例如：`192.168.100.1`，视你的配置而定）。
