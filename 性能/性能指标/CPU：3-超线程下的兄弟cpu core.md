## 开启超线程后，某个core的兄弟core
### 兄弟CPU
在 Simultaneous multithreading（SMT，也叫 **超线程**） 开启的情况下，每个物理 CPU Core 上会运行多个逻辑 CPU（线程）。这些逻辑 CPU 被称为**兄弟 CPU（sibling threads）**。

### 为什么要区分兄弟 CPU

#### 避免 CPU 资源竞争，提升性能

- 兄弟 CPU 共享**同一个物理核心的大部分硬件资源**（如 L1/L2 cache、执行单元、浮点单元等）。
- 如果在两个兄弟 CPU 上同时跑两个高负载、CPU密集型线程，它们会互相竞争这些资源，实际性能提升不如在两个独立物理 core 上运行。
- 场景：
    - 高性能计算（HPC）、低延迟交易系统、DPDK 数据面程序。

**做法**：
将重要任务绑到物理上独立的 core 上运行（避开兄弟 CPU），减少干扰。  
通过查看兄弟 CPU 列表，就能知道哪些逻辑 CPU 共享同一个 core。

#### 充分利用 SMT 带来的并行度

- SMT 的目的本就是为了**在同一个 core 上同时执行两个轻负载线程**，提高流水线利用率。
- 对于 I/O 密集型或轻量线程任务，把它们调度到兄弟 CPU 上可以更高效地利用核心资源。

**做法**：
合理地把**轻量任务**放在兄弟 CPU 上，使硬件执行单元不空闲。

#### 做 CPU 隔离 / 屏蔽核配置时要避免只隔离兄弟 CPU

- 在做 `isolcpus`、`nohz_full`、`rcu_nocbs` 这类隔离核调优时，如果只隔离了 core 上的一个逻辑 CPU 而没有隔离它的兄弟 CPU，仍然会有调度干扰。

**做法**：
所以需要知道兄弟 CPU 配对关系，一起隔离或一起分配。



### 查看一个CPU的兄弟CPU
**方法一**：
一般兄弟线程都是固定加一个数字，如下所示，此中是加`32`.
![](attachments/Pasted%20image%2020250916202808.png)

**方法二**：
```bash
# cat /sys/devices/system/cpu/cpu0/topology/thread_siblings_list
0,32
表示 CPU0 和 CPU32 是同一个物理 core 的两个线程（兄弟）。


# cat /sys/devices/system/cpu/cpu1/topology/thread_siblings_list
1,33

# cat /sys/devices/system/cpu/cpu16/topology/thread_siblings_list
16,48

# cat /sys/devices/system/cpu/cpu17/topology/thread_siblings_list
17,49
```
