# 介绍
**eRDMA (Elastic RDMA，弹性RDMA)**：eRDMA 是阿里云基于其自研的 神龙架构，在**虚拟化层和网卡硬件协同**实现的一种**私有化、云原生的 RDMA 技术**。

# 背景

# CIPU
**云基础设施处理器 CIPU（Cloud  Infrastructure Processing  Unit）** 是神龙架构（X-Dragon）演进到第 3 代及以后的核心硬件载体。
将其定义为取代传统CPU的新一代云计算体系架构的核心。在这个全新体系架构下，CIPU向下对数据中心计算、存储、网络等底层基础设施快速云化并进行硬件加速，向上接入飞天云操作系统，将全球数百万台服务器构建为一台超级计算机，实现资源的灵活编排和调度，给用户提供高质量弹性云计算算力集群。


# 阿里云的弹性RDMA：eRDMA
## 传统RDMA的优缺点
传统RDMA（前文讲RoCEv2有提过）需要专用网络和无损环境，难以在云上多租户VPC中落地。

传统RDMA为了解决TCP/IP的CPU负担重、延迟高的问题，实现了两大杀手锏：**内核旁路（Kernel Bypass）** 和 **零拷贝（Zero-Copy)**。
数据不再经过CPU和复杂的协议栈，而是由网卡上的DMA引擎直接在内存间搬运，这极大地降低了延迟和CPU开销。

但传统RDMA（如InfiniBand、RoCE）有两个致命缺点：**贵**且**难伺候**。
(1) 它需要专用的昂贵网卡和交换机
(2) 对网络质量极其敏感，需要“无损”网络，稍有丢包性能就急剧下降
这使其大规模部署非常困难。

## eRDMA
云厂家当中阿里云提出弹性RDMA（eRDMA），核心原理是：

**（1）网络复用**：直接运行在现有VPC网络上，无需改变组网架构。

**（2）虚拟化网卡（ERI）**：为虚拟机提供直通硬件的RDMA通道，实现内核旁路。

**（3）自研拥塞控制算法**：阿里云通过自研的拥塞控制（CC）算法，让eRDMA能够容忍VPC这种“有损”网络中的延迟抖动和数据包丢失。这使得它可以在普通以太网和IP网络上运行，而不依赖昂贵的专用网络设备。
通过实时感知网络质量，动态调整发送行为，在有损的云网络中依然保持高吞吐和低延迟。

**（4）软件兼容**：eRDMA在软件层100%兼容标准的RDMA Verbs接口和应用语义（主要是可靠的RC连接）。这意味着，为传统RDMA编写的HPC、AI训练等应用，几乎无需修改代码就能在eRDMA上运行，迁移成本极低。


eRDMA让高性能计算业务与普通云上业务在同一个VPC内“无缝互联”，真正实现了RDMA的云原生化。

```bash
我的理解：

从虚拟机（VM）发出并经过物理网络传输的 eRDMA 流量，依然会被封装在 VXLAN（或类似的 Overlay 隧道协议）报文中。
因为，虽然 eRDMA 实现了“内核旁路”和“硬件直通”，但这主要发生在虚拟机内部到宿主机网卡（HCA/ERI）这一段路径上。一旦数据离开宿主机进入云厂商的物理网络（Underlay），为了保持多租户隔离（VPC）和在现有三层网络上运行，它还是需要被封装。

虚拟化网卡（ERI）：主要是在虚机内部利用RDMA网卡硬件的能力，因为正常情况下，在虚机中无法看到宿主机上的物理网卡。物理利用RDMA物理网卡的bypass kernel, 零拷贝，节省CPU等能力了。

自研拥塞控制算法：因为中间网络中都是vxlan报文，无法利用RDMA网路的PFC，ECN等能力，因此需要在端上自研拥塞控制算法，实现有损流量的处理，进行动态调整。
```

## CIPU上：自研拥塞控制算法
eRDMA 采用了阿里云全栈自研的拥塞控制（CC）算法，使其不仅能在无损网络中工作，还能容忍 VPC 网络中的传输质量变化（如延迟、丢包等），在有损的网络环境中依然保持优异的性能表现，这使得它可以在普通以太网和IP网络上运行，而不依赖昂贵的专用网络设备。通过实时感知网络质量，动态调整发送行为，在有损的云网络中依然保持高吞吐和低延迟。

### 核心实现位置：神龙架构/CIPU
阿里云的 eRDMA 并非依赖传统的独立物理 RDMA 网卡，而是基于神龙架构的一款**原生带有云属性的 RDMA HCA（主机通道适配器）卡**；在神龙架构下，阿里云通过 CIPU（Cloud Infrastructure Processing Unit）实现了计算与网络、存储的解耦。你可以把 CIPU 理解成阿里云自研的、功能更强大的DPU。

CIPU 承担了虚拟化、网络协议栈处理以及硬件加速的重任。eRDMA的整个技术栈是“全栈自研”的，从硬件到算法都是闭环设计。作为这项能力的硬件基础，CIPU不仅负责VPC网络的虚拟化（VirtIO-Net设备），同时也集成了eRDMA的处理逻辑。这个新增的、独立的PCIe设备——弹性RDMA接口（ERI），就是专门用来处理RDMA协议和拥塞控制逻辑的。

所以，拥塞控制算法是直接“固化”并运行在CIPU芯片上的。

### CIPU芯片上运行的“智能软件算法”
核心逻辑是在 CIPU芯片上运行的“智能软件算法”。这个算法实现了两个关键突破：

**容忍“有损”网络**：传统RDMA需要交换机配合实现无损网络（如通过PFC流控），成本高且部署困难。eRDMA的自研CC算法，本质上是一个在端侧（即CIPU）运行的智能算法，它能根据VPC网络中实时的延迟、丢包等信号，动态调整发送速率，从而在普通、有丢包可能的“有损”VPC网络上，依然能维持高性能和低延迟。

**解决网络流量不均**：数据中心网络中，“大象流”可能导致交换机哈希冲突，造成链路拥塞。自研CC算法也具备智能的多路径能力，可以将这些大数据流打散，充分利用多条网络路径，避免拥塞。

### 需要交换机配合吗？
不依赖交换机做复杂配合。

这是它相对于传统RDMA（如RoCE）的一个重要优势。传统RDMA方案中，拥塞控制算法（如DCQCN）需要交换机支持并配置ECN水线、PFC等复杂功能。而eRDMA的设计目标就是简化部署，将复杂性从网络中心转移到端侧。

eRDMA的自研CC算法，其核心控制和决策都发生在CIPU端，因此它无需对底层交换机进行任何特殊配置或修改，就能在标准的、共享的VPC网络上工作。这使得eRDMA可以依托VPC网络进行大规模、低成本的部署，而不必依赖昂贵的、专为RDMA优化的交换机。

阿里云把eRDMA打包成了一种透明的网络能力，你可以像使用标准VPC一样申请和使用它，背后的拥塞控制、性能优化等复杂性，都被CIPU和自研算法处理好了。

## eRDMA和VPC的结合
传统 RDMA 通常需要构建独立的物理专网，而 eRDMA 最大的创新在于**底层链路完全复用 VPC 网络**。

**（1）共享网络架构**：eRDMA 依附于弹性网卡（ENI），通过创建弹性 RDMA 网卡（ERI）绑定到 ECS 实例上。ERI 完全复用了 ENI 所属的 VPC 网络。

**（2）无缝集成**：这种设计使得用户无需改变现有的业务组网，无需额外部署昂贵的 RDMA 专网交换机，即可在原有 VPC 网络下激活 RDMA 功能，实现秒级的大规模 RDMA 组网。

### 如何结合
**（1）物理层复用**：eRDMA不另起炉灶，它的底层链路完全复用你熟悉的VPC网络。这意味着阿里云不需要为eRDMA建设新的物理网络，你的业务组网也无需改变。

**（2）虚拟设备分离**：在服务器内部，eRDMA通过神龙架构的CIPU芯片，以软件定义硬件的方式实现。它在给虚拟机看的设备层做了“解耦”：
- 原先的 VirtIO-Net 设备继续负责标准的VPC网络通信（如TCP/IP）。
- 新增一个独立的 ERI（弹性RDMA接口） 设备，这个设备专门负责处理RDMA协议的数据包。

**（3）上层接口统一**：对应用开发者而言，看到的只是一个标准的RDMA网卡。你通过标准的Verbs API编程，完全感受不到底层VPC网络的存在。VPC的隔离、安全组等特性，对eRDMA来说依然有效。你可以把它想象成：在一条公共的VPC“马路”上，CIPU芯片为你划出了一条专用的“快速公交车道（ERI）”，你的高性能数据包走这条道，普通流量走原车道，互不干扰。

### 工作流程：如何启用并使用

要在云上使用eRDMA，流程非常简洁，体现了云原生的“简单”：

（1）选择硬件：购买ECS虚机实例时，选择支持eRDMA的实例规格（如GPU实例ebmgn7ex等）。

（2）一键开启：在购买配置中，勾选“弹性RDMA接口”选项。系统会自动为你安装好所需的eRDMA驱动和软件栈（如果是GPU实例，还会包含GPU驱动等），整个过程无需额外付费。

（3）应用适配（可选）：你的高性能应用可以直接调用标准的RDMA Verbs接口与eRDMA通信。

## eRDMA和传统的RDMA对比
**（1）成本与门槛**：传统 RDMA（如 InfiniBand、RoCE）依赖专用硬件和交换机，建设成本极高且运维复杂。eRDMA 是普惠的云上能力，无偿启用（购买实例时勾选即可），大幅降低了大众化场景的适配门槛。

**（2）弹性与扩展性**：传统 RDMA 网卡是独立的物理硬件，不支持热迁移。eRDMA 基于阿里云神龙架构/CIPU架构，原生带有云属性，支持在 ECS 使用过程中动态添加设备、支持热迁移，具备极强的弹性扩展能力。

**（3）组网规模**：传统 RDMA 强依赖无损网络，大规模组网困难。eRDMA 依托自研拥塞控制算法，可在 VPC 环境中支持秒级的大规模 RDMA 组网，适用于构建云上大规模紧耦合集群（如工业仿真、AI 训练、Redis 缓存等）。


|特性|**阿里云 eRDMA**|**传统 RDMA (InfiniBand/RoCE)**|
|---|---|---|
|**核心理念**|云原生、普惠、弹性|高性能计算、专用、昂贵|
|**网络依赖**|**有损网络**（容忍丢包，依靠自研CC算法）|**无损网络**（对丢包极度敏感，需要专用交换机）|
|**硬件成本**|**低**（复用VPC网络，无需专用设备）|**极高**（需要专用网卡和交换机）|
|**部署规模**|**大规模、弹性**（秒级组网，可达近10万级节点）|**受限**（规模部署困难，成本高昂）|
|**应用迁移**|**零修改**（完全兼容Verbs接口和RC语义）|N/A|
|**性能表现**|**高**（e.g., 双向200Gbps带宽，5-8μs时延）|**顶尖**（理论极限性能可能更高，但受限于部署规模）|

总结来说，eRDMA通过软件创新，在VPC这个通用平台上，以极低的成本和极高的弹性，复刻了传统RDMA的卓越性能。它让高性能网络不再是少数玩家的专属，而是成为了云上每个开发者都可以按需获取的通用能力。
