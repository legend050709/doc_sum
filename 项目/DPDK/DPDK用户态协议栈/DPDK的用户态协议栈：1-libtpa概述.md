# MPTCP支持
## 背景
MPTCP（Multipath TCP）是一种扩展的 TCP 协议，允许在单一 TCP 连接中同时使用多个网络路径传输数据。初次大规模应用部署 MPTCP 是在端侧移动网中苹果手机中的 Siri 助手，主要用于改善移动网络下的用户体验。

随着数据中心规模的指数级增长，特别是近年来众多高性能应用的兴起，传统TCP协议的单路径传输模式在某些场景下已难以满足高吞吐、低延迟、高可靠性等需求。比如以下的场景：
- 某台交换机存在转发路径黑洞，但由于控制面正常，并没有撤销其路由发布，最终导致所有经过该交换机转发的报文都被丢弃。
- 某一时刻流量有可能会集中在一条转发路径上，导致某条转发路径出现流量瓶颈，出现丢包、延时增大、抖动等现象，最终所有经过转发路径的业务都会受到影响。

## 为什么要选择 MPTCP来支持多路径
数据中心内需要支持多路径传输的协议。事实上，业界也有各种多路径自研协议的探索，大多数都是基于 UDP 的，却鲜有基于 TCP 的。那我们为什么要选择 MPTCP 呢？主要有以下几点原因：

- **服务连续性保障**：首先当然是其它多路径协议一样，主要是避免由于数据中心内部单个网络节点或者单条传输路径故障可能导致服务降级甚至中断，MPTCP 通过多路径冗余传输实现快速故障感知和切换。
    
- **带宽资源最大化**：单条物理链路的带宽通常很难满足某些场景的需求，MPTCP 可聚合多条物理链路带宽，最大化带宽资源利用率。
    
- **存量应用兼容性**：数据中心内存在大量的存量 TCP 应用，MPTCP 可以平滑的回退到 TCP，可以支持大规模存量服务的平滑迁移。
    
- **内核生态支持**：Linux 5.6 内核开始原生支持 MPTCP协议，为规模化部署提供了基础支撑。

## 为什么要选择基于 DPDK的用户态实现MPTCP呢？
- **高性能包处理能力**：众所周知，内核态转发是存在瓶颈的，特别是在某些高性能场景下，而DPDK是其中最著名的 内核旁路（Kernel Bypass） 技术之一，结合 DPDK 零拷贝、轮询模式、批量处理等加速，以满足高性能、低时延等场景需求
    
- **灵活性及可定制化能力**：用户态下可灵活实现多种包调度策略、拥塞控制、路径选择等，无需修改内核
    
- **资源扩展性**：DPDK天然支持多核并发处理，同时在容器、虚拟化等环境下可以很方便的结合 SRIOV （Single Root I/O Virtualization）等进行加速
