# 不同命令的inode的变化
## cp命令
### cp不同名文件

### cp同名文件
使用 `cp new old` 替换同名文件时，`old` 文件的 inode **不变**，但其内容被替换。
如果你对运行中的进程使用的共享模块so文件进行同名覆盖，就会出现`bus error 的 Segmentation fault`。

|**步骤**|**操作**|**结果**|
|---|---|---|
|**步骤 1**|`cp new old`|1. `cp` 命令会**打开** `old` 文件（inode不变）。 2. 它会**清空** `old` 文件的所有内容（截断）。 3. 它将 `new` 文件的内容**写入**到 `old` 文件中。|
|**inode 变化**|`old` 文件的 inode **不变**。|文件的权限、所有者、创建时间等元数据保持不变（但修改时间会更新）。|
|**旧文件**|旧文件的内容**被覆盖**，而不是旧文件被删除。|磁盘上的数据块被 `new` 文件的内容所取代。|
|**原子性**|**非原子操作**。|如果复制过程中断电或发生错误，`old` 文件可能会损坏或只包含部分内容。|



## mv命令
1）使用新文件名建立目录项；  
2）删除带有原来文件名的目录项；

### mv = rm + cp
使用 `mv new old` 替换同名文件时，旧的 `old` 文件被删除，文件的 inode **会变**，换成新的inode。

即使是mv到一个已经存在的目标文件，会先删除目标文件的目录项，所以如果你对运行中的程序的共享模块so文件进行这种操作的话不会有问题，因为新的so文件inode号变了。

|**步骤**|**操作**|**结果**|
|---|---|---|
|**步骤 1**|`mv new old`|1. 链接器找到 `old` 文件在目录中对应的 **目录项**。 2. 它将 `old` 文件的目录项**删除**（unlink）。 3. 它将 `new` 文件**重命名**为 `old`。|
|**旧文件**|旧的 `old` 文件**被删除**（unlink）。|如果没有其他硬链接指向它，旧的 `old` 文件的 inode 引用计数降为 0，数据块被释放。|
|**原子性**|**原子操作**。|这是一个单一的文件系统操作（删除一个目录项，创建另一个目录项），要么成功，要么失败，不会出现中间状态。|

## rm命令

1）减少链接数量，如果链接数为0释放inode（inode号码可以被重新使用）；  
2）如果inode被释放，则数据块放到可用空间列表中；  
3）删除目录中的目录项

## ln命令
### 硬链接：`ln 源文件名 链接名`
多个硬链接指向同一个inode号；  

用rm来删除硬链接文件：  
1）仅仅是减少链接数量；  
2）只要有一个链接存在文件就存在；  
3）当链接数为零，文件就被删除了。

### 软链接：`ln -s 源文件名 链接名`
符号链接的内容就是它所指向的文件名；符号链接文件有自己的inode；  

rm删除的话只是删除这个链接文件。
