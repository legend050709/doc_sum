# 背景
我们都知道，将源代码转换为可执行的程序，通常要经过三个步骤：编译、链接、运行。不同的编译语言，在这三个步骤中所进行的操作又有些不同。

C语言作为一门静态类语言，在编译阶段就已经确定了所有变量的数据类型，同时也确定好了要调用的函数，以及函数的实现。

而Objective-C语言是一门动态语言。在编译阶段并不知道变量的具体数据类型，也不知道所真正调用的哪个函数。只有在运行时间才能检查变量的数据类型，同时在运行时才会根据函数名查找要调用的具体函数。在这样在程序没运行的时候，我们并不知道调用一个方法具体会发生什么。

Objective-C语言把一些决定性的工作从编译阶段、链接阶段推迟到运行时阶段的机制，使得Objective-C变得更加灵活，我们甚至可以在程序运行的时候，动态的去修改一个方法的实现，这也为大为流行的热更新提供了可能性。

要实现Objective-C语言 运行时机制的一切基础就是Runtime。


# 定义
**runtime 是一个通用抽象的术语，指的是计算机程序运行的时候所需要的一切代码库，框架，平台，环境等**。
runtime 描述了**程序运行时候**执行的软件/指令， 在每种语言有着不同的实现。可大可小，在 C 中，runtime 是库代码， 等同于 C runtime library，一系列 C 程序运行所需的函数，在 Java 中，runtime 还提供了 Java 程序运行所需的虚拟机等。

实际上编程语境中的 runtime 大概有三个含义，分别指：
- **程序运行的时候，即程序生命周期中的一个阶段**
比如：Rust 比 C 更容易将错误发现在编译时而非运行时。

## 狭义上的runtime
狭义的运行时。给它的定义是**支撑程序跑起来的代码和环境**。
这里其实要分成两个来讲，一个是运行时库，一个是运行时环境，大家嫌麻烦有时候都会缩写成“运行时”。
### 运行时库
这个其实很好理解。还是拿C代码做例子，我们引用了 stdio.h 这个头文件，其实就是用了C语言的标准库。
这个库在Windows上一般是 CRT，全称是 C Runtime Library，在 Linux 上一般是 glibc，全称是 GNU C Library。在链接的时候用了这些库，这些库就是程序运行所必须的。

### 运行时环境
前面我们讲的运行时库是代码，运行时环境就不一定了，它还可能是一个独立的程序。 
在这儿我把运行时环境分成了三种：
![](attachments/Pasted%20image%2020231007180509.png)


- 第一种是C/C++/Rust，这种是“无”运行时。
这里的“无”加了一个引号，因为大部分情况下它还是依赖操作系统的，操作系统也可以认为是一种“运行时环境”。
> 注：此中提到的“无”运行时的C/C++/Rust，它们不光没有运行时，还可以脱离运行库，甚至可以脱离操作系统。在C/C++里你可以不引用任何库，Rust里有一个专门的特性叫 no_std，干的也是类似的事情。有人可能想问了为什么要脱离标准库呢？没有标准库那代码还怎么写？脱离标准库提供了一个很牛的能力，就是直接和硬件交互。换句话说C/C++/Rust是可以用来编写操作系统内核的。没了标准库代码怎么写呢？确实会非常非常难写，基本就相对于写高级版的汇编了，操作系统内核就是在这种艰难的环境中写出来的。另一方面这也解释了为什么我们几乎见不到用Java/C#/Python编写的操作系统，因为主流的运行环境中它们没有提供这种面向硬件(bare metal)的编程环境。

- 第二种是轻运行时
我用的例子是Golang，如果大家还知道别的也可以补充。它的运行时是和代码打包到一起的，相对轻量一些。

- 最重的是第三种，我把它们归到了“重运行时”这个类别，
例子就是**Java(JVM)，Python(CPython)，还有 C#(.NET Runtime)**。
它们的运行时环境是需要单独安装的，而且一般还不小，几十兆上百兆都是正常的，可以说是很“重量级”了。
> 注：此中提到“重运行时”的语言，我们在说它的运行时的时候，往往是既包含运行时环境又包含运行时库。比如JRE里面，其实既包含了JVM这个运行时环境，又包含了一整套的Java标准库。本质上你很难脱离Java标准库去写Java。C#和Python也是类似的。标准库跟运行时环境几乎总是同时出现的。

# runtime的优缺点
说了这么多有没有运行时到底有啥差别呢，或者说C/C++跟Java在运行环境上，哪些地方有差别呢？
一句话来讲就是，**“运行时”相当于一个小助手，可以帮你的程序干一些脏活累活，让你在编程的时候更轻松**。

![](attachments/Pasted%20image%2020231007180600.png)

- 在内存管理层面 
首先“无”运行时的语言在内存管理上偏向手动
最好的例子就是C语言了，内存管理全手动。C++和Rust这种在内存管理上有所进步，但是跟有运行时的Java/Python等还是有一定距离。有运行时的语言内存管理交给VM层面，大大降低了程序员编程时的负担。 

- 在线程模型这个层面
“无”运行时的语言在线程模型上往往会直接依赖于操作系统
而有运行时的Java和C#这种，它往往会有自己的一个线程机制，而且跟系统不一定是完全对应的。例如C#当中的 managed thread 和 OS thread 并不是完全对应的。Golang 当中的协程也是一个很好的例子。它们都实现了自己的轻量级调度框架，并不直接依赖操作系统。

- 在系统调用层面
“无”运行时的语言可以直接和操作系统交互，而有运行时一般是要通过运行时来交互的。

- 在运行效率层面
第四点就是老生常谈的问题了，“无”运行时的C/C++等运行效率上相对会高一些，而有运行时就增加了一些负担，不考虑JIT的情况下运行效率会差，有JIT的话效率能提升很多。
