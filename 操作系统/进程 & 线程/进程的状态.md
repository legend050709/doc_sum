# 进程的状态分类
在top和ps命令中有一列显示进程状态，分别有如下值
```bash
man ps
```
![](attachments/Pasted%20image%2020240422151121.png)

在 Linux 操作系统中，进程的状态可以分为以下完整的分类：

1. Running（**TASK_RUNNING**：运行）：进程正在执行或准备执行。在多核系统上，多个进程可以同时处于运行状态。
    
2. Sleeping（睡眠）：进程暂时被挂起，等待某个事件的发生。这包括等待 I/O 操作完成、等待信号量、等待定时器等。睡眠状态又可以分为可中断睡眠和不可中断睡眠两种情况。
    
    - 可中断睡眠（S状态：Interruptible Sleep）：进程在等待某个事件时，可以被信号中断并唤醒。例如，当进程等待读取磁盘数据时，如果接收到一个中断信号，进程可以被唤醒并执行其他操作。
        
    - 不可中断睡眠（D状态：Uninterruptible Sleep）：进程在等待某些事件发生时，不会被信号中断。这通常是因为进程在执行一些关键的操作，如等待磁盘上的数据完全加载到内存中。在不可中断睡眠状态下，进程无法响应中断信号。
        
3. Stopped（停止）：进程暂停执行，直到接收到一个特定的信号才能继续执行。常见的例子是通过调试器将进程设置为停止状态，以进行调试操作。
    
4. Zombie（僵尸）：进程已经终止，但其退出状态仍然保留在进程表中，直到父进程调用 `wait()` 系统调用来获取子进程的退出状态。僵尸进程不占用系统资源，但需要父进程对其进行清理，否则它们会一直保留在进程表中。
    
5. Traced（跟踪）：进程被其他进程（跟踪进程）跟踪，跟踪器可以监视和控制跟踪进程的执行。
    
这些状态涵盖了进程在 Linux 中的所有可能状态。通过监视进程的状态，可以了解进程的执行情况和可用性，并对系统进行故障排查和性能优化。



## Stopped状态
怎样让一个进程进入`中止状态`呢？
举个例子，假设程序在运行过程中，现在要求用户输入，而有些时候，用户并不想立即输入，这时用户可以通过`control + z`的键盘组合键来中止这个输入的操作，让这个进程变成`中止状态`：
```c
[root@localhost ~]# cat input.c
#include <stdio.h>

int main(void){
  int num = 0;
  printf("Input a number: ");
  scanf("%d", &num);


  printf("Number is %d\n", num);
  return 0;
}
[root@localhost ~]# gcc -o input input.c
[root@localhost ~]# ./input
Input a number:
```

中止前进程状态：
```c
[root@localhost ~]# ps -aux | grep input
root      7608  0.0  0.0   4220   356 pts/0    S+   11:20   0:00 ./input
```

键入`control + z`后再查看进程状态：
```c
[root@localhost ~]# ./input
Input a number: ^Z
[1]+  已停止               ./input
[root@localhost ~]# ps -aux | grep input
root      7608  0.0  0.0   4220   356 pts/0    T    11:20   0:00 ./input
```

通过`fg`命令恢复进程状态：
```c
[root@localhost ~]# fg
./input
123
Number is 123
```
## Traced 状态
当使用了ptrace跟踪后，所有发送给被跟踪的子进程的信号(除了SIGKILL)，都会被转发给父进程，而子进程则会被阻塞，这时子进程的状态就会被系统标注为TASK_TRACED，而父进程收到信号后，就可以对停止下来的子进程进行检查和修改，然后让子进程继续运行。

# 进程S状态
处于 S 状态的进程因为等待某某事件的发生（比如等待socket连接、等待信号量），而被挂起。这些进程的task_struct结构被放入对应事件的等待队列中。

当这些事件发生时（由外部中断触发、或由其他进程触发），对应的等待队列中的一个或多个进程将被唤醒。

# 进程D状态
 TASK_UNINTERRUPTIBLE存在的意义就在于，内核的某些处理流程是不能被打断的。如果响应异步信号，程序的执行流程中就会被插入一段用于处理异步信号的流程（这个插入的流程可能只存在于内核态，也可能延伸到用户态），于是原有的流程就被中断了。在对某些硬件进行操作时（比如进程调用read系统调用对某个设备文件进行读操作，而read系统调用最终执行到对应设备驱动的代码，并与对应的物理设备进行交互），可能需要TASK_UNINTERRUPTIBLE状态对进程进行保护，以避免进程与设备交互的过程被打断，造成设备陷入不可控的状态。
 
> 即：不可中断状态，表示进程正在跟硬件交互，为了保护进程数据和硬件的一致性，系统不 允许其他进程或中断打断这个进程。例如对某些硬件设备进行操作时刻（等待磁盘Io,等待网络io、其他外设 IO等等）。

**进程处于D状态一般情况下很短暂，不应该被top或者ps看到。
如果进程在top和ps看到长期处于D状态，那么可能进程在等待IO时出现了问题导致进程一直等待不到IO资源** 。

与TASK_INTERRUPTIBLE状态类似，进程处于睡眠状态，但是此刻进程是不可中断的。**不可中断，指的并不是CPU不响应外部硬件的中断，而是指进程不响应异步信号**。

## 查看
处于`uninterruptible sleep`状态的进程通常是在等待IO，比如磁盘IO，网络IO，其他外设IO，如果进程正在等待的IO在较长的时间内都没有响应，那么就很会不幸地被ps看到了，同时也就意味着很有可能有IO出了问题，可能是外设本身出了故障，也可能是比如挂载的远程文件系统已经不可访问了（由down掉的NFS服务器引起的D状态）。

1. 使用 `ps` 命令：在终端中输入 `ps -eo pid,state,cmd | grep "^D"` 命令。该命令将列出所有处于 D 状态的进程及其进程 ID（PID）、状态和命令行信息。

## 危害
长期处于 D 状态的进程在一般情况下并不会造成直接的危害，因为它们不占用 CPU 时间，并且不会影响其他正常运行的进程。然而，长时间处于 D 状态可能会导致以下问题：

1. 资源占用：这些进程仍然在占用系统资源，如内存和进程表项。如果大量进程长时间保持在 D 状态，可能会导致系统资源的耗尽。
    
2. 响应性降低：如果关键的系统任务或操作需要等待长时间处于 D 状态的进程完成，可能会导致系统的响应性下降。
    
3. 调试困难：由于长时间处于 D 状态的进程无法被中断，对于开发人员来说，诊断和调试这些进程可能会更加困难。
    
4. 潜在系统稳定性问题：长时间处于 D 状态的进程可能暗示系统中存在硬件故障、设备驱动程序问题或内核 Bug。这些问题可能对系统的稳定性产生潜在影响。
    

如果系统中出现大量处于长时间 D 状态的进程，建议进行系统故障排查，并尽快解决引起这些问题的根本原因。这可能涉及检查硬件、设备驱动程序、文件系统以及相关的内核配置和补丁。

## 原因
在 Linux 中，长期处于 D（Uninterruptible Sleep）状态的进程通常是由于以下原因之一：

1. I/O 等待：进程正在等待某个 I/O 操作完成，例如读取磁盘数据或网络操作。这是最常见的 D 状态原因之一。
    
2. 设备驱动程序问题：进程与设备驱动程序之间可能存在问题，导致进程无法正常完成操作并进入睡眠状态。
    
3. 文件系统问题：进程可能由于文件系统问题而无法继续执行，例如等待文件系统锁定或未处理的文件系统错误。
    
4. 内核 Bug：某些情况下，进程可能在内核中遇到 Bug 或其他异常情况，导致无法正常恢复。

## 恢复
正是因为得不到IO的相应，进程才进入了`uninterruptible-sleep`状态，所以要想使进程从`uninterruptible-sleep`状态恢复，就得使进程等待的IO恢复。
比如如果是因为从远程挂载的NFS卷不可访问导致进程进入`uninterruptible-sleep`状态的，那么可以通过恢复该NFS卷的连接来使进程的IO请求得到满足。

## 其他
### 无法使用Kill -9
**处于D状态的整个进程无法被`kill -9` 掉；很多常用的调试工具，比如 `strace`, `pstack` 等也都失灵了。**此时如果要处理掉这个D进程，那么只能重启整个系统才会恢复。
如果为了想要杀掉 D 状态的进程，而去杀掉它的父进程（通常是shell，在shell下允许某进程，然后某进程转入D状态），就会出现这样的状态：他们的父进程被杀掉了，但是他们的父进程 PID 都变成了1，也就是 init 进程，D状态的进程会变成僵尸进程。


> `kill -9` 只是给进程发送了一个 `SIGKILL` 信号，当一个进程处于特殊状态时（信号处理，或者系统调用中）会无法处理任何信号，包括 `SIGKILL` 也不能被正确处理，导致进程不能被立即杀掉，也就是我们常说的 D 状态（不可中断的睡眠状态）。那些常用的调试工具 （比如 `strace`、`pstack` 等）一般也是利用某个特殊的信号来实现的，在这种状态下也是无法使用。

### 查看堆栈
此时可能无法使用pstack 查看堆栈。
 Linux 下提供了 procfs（就是 Linux 下的 `/proc` 目录）, 通过它就可以看到任何一个进程的当前内核调用栈。
