# 概述
《深入理解Linux内核-第五章》开头的一句话，很形象地把中断和系统调用两个不相关的概念联系了起来，巧妙地找到了这二者之间的相似处。
“你可以把内核看做是不断对请求进行响应的服务器，这些请求可能来自在CPU上执行的进程，也可能来自发出中断的外部设备。老板的请求相当于中断，而顾客的请求相当于用户态进程发出的系统调用”。

# 区别与联系
软中断和系统调用一样，都是CPU停止掉当前用户态上下文，保存工作现场，然后陷入到内核态继续工作。
二者的唯一区别是系统调用是切换到同进程的内核态上下文，而软中断是则是切换到了另外一个内核进程ksoftirqd上。

# 开销对比
每次中断的耗时分为2部分：
一是上下文切换开销，二是软中断内核执行开销。
## 软中断和系统调用
事实上，早期的系统调用也还真的是通过汇编指令int（中断）来实现的，当用户态进程发出int $0x80指令时，CPU切换到内核态并开始执行system_call函数。后来大家觉得系统调用实在是太慢了，因为int指令要执行一致性和安全性检查。后来内核使用了Intel提供的“快速系统调用”的sysenter指令，才算是和中断脱离了一点点干系。
**而软中断必须得进行这些检查，所以从这点上来看，中断的开销应该是比系统调用的开销要多的。**

**从实验数据来看，系统调用开销是200ns起步。从实验数据来看，一次软中断CPU开销大约3.4us左右。**

## 软中断和进程上下文切换
和进程上下文切换比较起来，进程上下文切换是从用户进程A切换到了用户进程B。而软中断的上下文切换是从用户进程A切换到了内核线程ksoftirqd上。  
而ksoftirqd作为一个内核控制路径，其处理程序比一个用户进程要轻量，所以软中断的上下文切换开销相对比进程切换要稍小一些。大家感兴趣的，可以继续阅读《深入理解Linux内核》的-第五章。

**根据前文的实验结果，进程上下文切换开销是3us-5us。**
