# 概述
期望DNS服务可以提供就近访问、智能解析（基于不同的client ip解析出不同的结果）、负载均衡、容灾切换、健康检查。

# 名词解释
## 就近访问

已知：对于一个region，存在多个AZ，一个AZ又有多个机房。
就近访问存在两种，第一种是：
**（1）dns请求的就近访问**
一个是client请求dns解析的就近访问。这样可以在每个机房都部署DNS集群，对外发布相同的Anycast IP，那么每个机房的client 就近访问本机房的DNS集群，本机房的DNS服务都挂掉，再访问其他机房的DNS服务。

**（2）client访问服务的就近访问**
一个域名，存在多个IP，为了容灾，服务可能部署在不同的机房。那么client请求该域名的时候，dns服务器应该返回距离client ip最近（比如：和client同机房）的 域名的ip给client，这样client后续对于该服务的访问就是就近访问。

## 负载均衡
一个域名，存在多个IP；client进行域名请求时，返回多个IP，每次返回的 顺序都是随机的，client访问服务的时候，取第一个ip进行访问，这样就可以做到对于服务的负载均衡。

注：一般而言，域名对应的ip，一般是LB的VIP。即所层负载均衡。

**（1）第一层负载均衡**：
域名对应多个IP。


**（2）第二层负载均衡**：
四层LB都是集群形式部署，形成了VIP的ECMP，这样四层LB的集群也可以进行负载均衡。

**（3）第三次负载均衡**：
四层LB下挂载了多个后端服务器，在多个后端服务器上进行负载均衡。

**（4）第四层负载均衡**：
一般四层LB后是七层LB，七层LB也可以配置负载均衡，比如 图片服务的多个服务器之间的负载均衡，视频服务的多个服务器的负载均衡，文本服务的多个服务器的负载均衡等。


## 健康检查

比如，一个域名下存在多个IP，client进行域名请求之后，获取到IP进行访问，其实是无法感知该IP所在的机器是否正常，以及业务服务是否正常的；如果该机器不正常，或者业务服务不正常，那么此时对于该IP进行业务访问，其实是有损的。

因此，对于一个域名存在多个IP，需要探测各个IP是否正常。
如果业务对于这个域名，仅仅访问比如443端口「即域名对应的IP为业务独占，且只访问某一个Port」，那么甚至需要探测该IP+443端口是否正常。

client进行域名请求时，仅仅返回那些健康的IP，而不是返回配置的本区域的所有IP。

## 容灾切换

容灾切换，往往可以和健康检查一起来配合使用；
比如，一个域名在每个机房都对应一些IP，如果某个机房都挂掉，那么就可以将其他机房的IP返回给Client。

# 设计

## 健康检查
如果是自研的 DNS系统，那么可以将健康检查放在DNS中进行实现。
如果是使用bind9这种开源系统，且不想要自己开发。那么就需要在bind9的上层实现一层健康检查、容灾切换的控制层，这就就叫dns-controller。

对于用户的配置下发，先经过dns-controller，dns-controller 对某个域名的多个IP 进行健康检查（健康检查可以是ping ip，也可能是 telnet ip + port, 视具体的配置），只下发那些健康 的 IP下去。 

## 容灾切换
一个域名，对应多个地址池，一个地址池中存在多个IP。
一个地址池，可以理解为一个IDC的IP，是为了就近访问/智能解析。

一个域名，配置的多个地址池，可以是：
**（1）存在多个主地址池**
为了就近解析。
一般而言，为了就近访问，每个区域/IDC都有一个主地址池。

**（2）主地址池，含有对应的备地址池**
当主地址池中的IP都不健康时，返回备地址池中健康的IP。
当主备地址池中的ip都不健康时，兜底策略就是直接返回本区域的全部主地址池。

**（3）主备的配置**
多个主地址池，可以含有相同的备地址池。
其他的主地址池，也可以作为另外一个主地址池的备地址池。
两个主地址池，也可以互为主备地址池。
n个主地址池，对于每个主地址池，另外的n-1主地址池，也可以作为自己的备。

## 负载均衡
client对于某个域名的请求，如果返回多个IP，client一般取第一个IP进行访问。
因此，返回给Client的多个IP中哪个IP是第一个IP就影响到负载均衡。

如果 dns 是自研系统，那么可以基于调度算法，来决定第一个IP；
比如：rr调度算法、wrr调度、conhash调度等等。

如果是 dns-controller, 后面是 bind9, 那么 dns-controller 是无法控制哪个 IP 是第一个ip，bind9中存在配置使用何种调度算法返回第一个 IP。
