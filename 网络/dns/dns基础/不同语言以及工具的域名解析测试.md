# dns特性
## 使用glibc库的服务的dns解析
服务基于glibc开发的各类网络服务，我们能见到的一些编程语言和开发框架（比如ping, curl ）最终均会调用到glibc的网络解析的函数（如 gethostbyname or getaddrinfo）。
因此，这类程序能够使用/etc/hosts文件，以及 NSCD提供的缓存服务。

> 当然了如果是应用端自己用socker编写了一个网络client就无法使用NSCD提供的缓存服务，比如DNS领域常见的dig命令不会使用NSCD提供的缓存。

## dns查询顺序
查询的优先级：本地hosts文件 => 本地缓存 => 本地DNS区域文件。

DNS域名解析的时候先根据 /etc/nsswitch.conf（name service switch） 配置的顺序进行dns解析，一般是这样配置：hosts:      files dns myhostname
【files代表 /etc/hosts ； dns 代表 /etc/resolv.conf】。

如果本地有DNS Client Cache，先查询完hosts文件后，没查到，走Cache查询，最后是 /etc/resolv.conf。 所以有时候看不到DNS网络包。Linux下nscd可以做这个cache。

> **注意：dig /nslookup 是自己用socket编写的 网络client，没有用到glibc的 getaddrinfo. 因此 dig命令不会查询hosts文件，不会使用NSCD提供的缓存**。

# glibc域名解析函数
glibc 的解析器(revolver code) 提供了下面两个函数实现名称到 ip 地址的解析。
## gethostbyname
gethostbyname 函数以同步阻塞的方式提供服务, 没有超时等选项, 仅提供 IPv4 的解析.

## getaddrinfo
getaddrinfo 则没有这些限制, 同时支持 IPv4, IPv6, 也支持 IPv4 到 IPv6 的映射选项.
包含 Linux 在内的很多系统都已废弃 gethostbyname 函数, 使用 getaddrinfo 函数代替. 不过从现实的情况来看, 还是有很多程序或网络库使用 gethostbyname 进行服务.

## glibc中对/etc/resolv.conf中的 rotate 的处理
glibc 2.2.5(2010年的版本），如果有rotate逻辑就是把第一个nameserver总是丢到最后一个去（为了均衡nameserver的负载，保护第一个nameserver）。
在2017年这个代码逻辑终于改了，不过还不是默认用第一个，而是随机取一个，rotate搞成random了。

也就是2010年之前的glibc版本在rotate模式下都是把第一个nameserver默认挪到最后一个（为了保护第一个nameserver），这样rotate模式下默认第一个nameserver总是/etc/resolov.conf配置文件中的第二个。到2017年改掉了这个问题，不过改成随机取nameserver, 作者不认为这是一个bug，他觉得配置rotate就是要平衡多个nameserver的性能，所以random最公平，因为大多程序都是查一次域名缓存好久，不随机轮询的话第一个nameserver压力太大

## dns缓存nscd
线上开启 `nscd` 前, 建议做好程序的测试, `nscd` 仅支持通过 `glibc` 标准机制运行的程序, 没有基于 glibc 运行的程序可能不支持 `nscd`.

比如，go, perl 等编程语言网络库的解析函数是单独实现的, 不会走 `nscd` 的 `socket`, 这种情况下程序可以进行名称解析, 但不会使用 nscd 缓存.

# 常见语言以及工具
## go
golang 默认有独立的获取方式不调用`getaddrinfo`。分别使用2个socket发送A记录和AAAA记录请求。发包使用`write`，收包使用`read`。会调用`connect`，里面存在目的地址信息。

## c(java以及python)等
c/java/python：使用`getaddrinfo`进行解析  （urllib2库）；使用同一个socket同时发送2个DNS请求（A和AAAA）。发包调用`sendmmsg`，收包调用`recvfrom`。会调用`connect`，里面存在目的地址信息。

```python3
import socket

def query_dns(domain):
    try:
        ip_address = socket.gethostbyname(domain)
        return ip_address
    except socket.gaierror:
        print("Unable to resolve domain name")

if __name__ == "__main__":
    domain_name = "www.baidu.com"
    ip_address = query_dns(domain_name)
    print(f"The IP address of {domain_name} is {ip_address}")
```

## 工具
### dns工具
`nslookup`、 `host` 、`dig`属于`bind-utils`包，用的`bind-libs`包里的库进行解析。
dig使用自己实现的dns请求发送，调用`sendmsg`发包和`recvmsg`收包。dig使用的是`unconnect` UDP发包，不会调用`connect`，源目的信息直接存储在`sendmsg`调用的`msghdr`结构体中。

### 其他工具
`curl`、`ping` 命令使用`getaddrinfo`进行解析。
