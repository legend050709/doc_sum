# 定义
**变长数组（Variable Length Array，简称VLA）**：可变长数组（VLA）特性，在编译时不确定数组大小，其大小不固定，而是在程序运行时才确定数组的长度，

## 传统的 C 语言数组
`ANSI C 标准「比如：C89 标准」`规定：定义一个数组时，数组的长度必须是一个常数，即数组的长度在编译的时候是确定的。在ANSI C 中定义一个数组的方法如下：
```c
int arr[10];  // 固定大小为10的整型数组
```
这种数组在编译时就确定了大小，一旦定义就不能改变。

## C99 新标准下的变长数组
`C99 新标准`规定：`可以定义一个可变长数组（VLA）`。
```c
int n = 5;  // n可以是变量  
int arr[n]; // 数组大小由变量n决定
```
也就是说，数组的长度在编译时是未确定的，在程序运行的时候才确定，甚至可以由用户指定大小。

### 动态内存分配来模拟动态数组
当然，我们也可以采用指针变量和动态内存分配的方式，来模拟动态数组的行为，可以使用 malloc 或者 calloc 相关的函数，在程序运行时进行动态内存分配。
```c
#include <stdio.h>
#include <stdlib.h>

int main() {
    int *arr = NULL;
    int n = 10;
    // 动态分配数组
    arr = (int *)malloc(n * sizeof(int));

    if (arr == NULL)return -1;
    // 使用数组
    for (int i = 0; i < n; i++) {
        arr[i] = i;
    }

    // 打印数组内容
    for (int i = 0; i < n; i++) {
        printf("%d \mn ", arr[i]);
    }

    // 释放内存
    if(NULL != arr)free(arr);

    return 0;
}
```


# 误解：C 语言不能定义变长数组？
## 误解的由来
这个误解主要是因为：
(1) 早期的 C 标准（C89/C90）确实不支持变长数组
(2) 某些编译器可能不完全支持
(3) 人云亦云，讲解 C 语言的老师或教材可能过时了

就这样，"C 语言不能定义变长数组"的说法就在编程圈子里流传开了...

## 真相：C99标准早就支持变长数组了！
从1999年的 C99 标准开始，C 语言就正式支持变长数组了！
```c
#include <stdio.h>  
  
int main() {  
    printf("请输入数组大小：");  
    int size;  
    scanf("%d", &size);  
      
    // 这就是变长数组！大小由用户输入决定  
    int numbers[size];  
      
    printf("请输入%d个整数：\n", size);  
    for(int i = 0; i < size; i++) {  
        scanf("%d", &numbers[i]);  
    }  
      
    // 计算平均值  
    int sum = 0;  
    for(int i = 0; i < size; i++) {  
        sum += numbers[i];  
    }  
      
    printf("平均值是：%.2f\n", (float)sum / size);  
      
    return0;  
}
```
这段代码符合 C99 标准，但要记住，变长数组这个特性并非所有编译器都支持！  比如：VS 自带的 `MSVC (Microsoft Visual C++)` 就不支持变长数组。

# for循环中的变长数组VLA

在C语言中，如果使用变量长度数组（Variable Length Array，简称VLA），那么可以在每次循环中定义长度不同的数组。VLA是C99标准引入的特性，允许使用变量来指定数组的长度。但是，需要注意的是：
(1) VLA在栈上分配空间，因此数组长度不能过大，否则可能导致栈溢出。
(2) VLA在每次进入作用域时创建，离开作用域时自动释放（无需手动释放）。
(3) 循环的每次迭代都会创建一个新的数组，长度可以不同。

## 关键特性

**自动内存管理**：
- VLA 在栈上分配内存
- **离开作用域时自动释放**（无需手动 `free`）
    
 **长度动态**：
- 长度可以是变量（如 `len = i+1`）
- 每次循环可以不同
    
**作用域规则**：
- 数组仅在循环块内有效
- 每次迭代都是独立的新数组

## 注意事项


**作用域限制，不可跨作用域使用**：VLA定义在循环体内，所以每次循环都会重新创建一个新的数组，上次循环的数组在循环结束时自动释放（离开作用域时栈帧调整）。
```c
   int* func() {
       int len = 10;
       int arr[len];  // VLA
       return arr;    // ❌ 严重错误！返回栈内存地址
   } // arr 在此被销毁
```

**栈大小空间限制**：如果数组长度很大，不建议使用VLA，因为栈空间有限（通常几MB），可能导致栈溢出。对于大数组，应使用动态内存分配（malloc/free）。

**C标准支持**：VLA是C99标准引入的，但在C11标准中变为可选特性（编译器可以选择不支持）。请确保你的编译器支持C99或更高版本（如GCC默认支持）。如果使用不支持VLA的编译器（如一些嵌入式编译器），则无法使用。

 **性能**：VLA的分配和释放通常在栈上完成，速度较快，但分配和释放操作本身可能比堆分配（malloc）有更多的限制（比如大小不能动态改变，且受栈大小限制）。

## 结论

|特性|VLA|malloc|
|---|---|---|
|**内存位置**|栈|堆|
|**最大大小**|小（KB级）|大（GB级）|
|**生命周期**|自动（作用域结束释放）|手动（需free）|
|**初始化**|不能直接初始化（`int a[n] = {0}` ❌）|可用calloc初始化|
|**错误处理**|失败时崩溃（无检查）|可检查NULL|
|**标准支持**|C99起|所有标准|

### 如何选择

对于大多数实际应用，特别是涉及大数组或需要跨函数使用时，`malloc` 仍是更安全灵活的选择。但对于小型临时数组（如数学计算中的矩阵），VLA 可以提供更简洁的代码结构。

#### 何时使用 VLA：

- 数组较小（KB 级别）
- 生命周期限于当前作用域
- 需要简化代码（避免 malloc/free）
- 确定编译器支持 VLA

#### 何时使用 malloc：

- 数组较大（MB+ 级别）
- 需要跨函数使用
- 需要初始化内存为零
- 需要精细控制内存生命周期
- 需处理分配失败情况

## 范例
```c
# cat test_for_vla.c
#include <stdio.h>

int main() {
    for (int i = 0; i < 5; i++) {
        int len = i + 1;  // 每次循环长度不同（1→5）
        int arr[len];     // 声明VLA

        // 填充数组
        for (int j = 0; j < len; j++) {
            arr[j] = j * 10;
        }

        // 打印数组
        printf("Iteration %d [Len=%d]: ", i, len);
        for (int j = 0; j < len; j++) {
            printf("%d ", arr[j]);
        }
        printf("\n");
    } // 数组在此自动销毁

    return 0;
}
```

测试结果：
```bash
# gcc test_for_vla.c -o test_for_vla
# ./test_for_vla
Iteration 0 [Len=1]: 0
Iteration 1 [Len=2]: 0 10
Iteration 2 [Len=3]: 0 10 20
Iteration 3 [Len=4]: 0 10 20 30
Iteration 4 [Len=5]: 0 10 20 30 40
```

# 变长数组VLA的优缺点
## 优点
**（1）动态分配大小：**
使用可变长数组，可以根据实际需要，在程序运行时分配数组的带下，在处理不确定大小的数据集时，非常有用。

**（2）减少内存浪费：**
由于可变长数组是运行时才确定其大小的，因此可以避免在编译时分配固定内存，造成内存浪费。

## 限制和注意事项
虽然变长数组很方便，但也有一些限制和注意事项：
### 只能在函数内部定义
变长数组只能在函数内部定义，不能作为全局变量或静态变量。
```c
// 错误写法  
int n = 10;  
int global_arr[n];  // 编译错误！  
  
// 正确写法  
void func(int n) {  
    int local_arr[n];  // 这样可以  
}
```
### 不能初始化
变长数组定义时不能直接赋初值。
```c
int n = 5;  
int arr[n] = {1, 2, 3, 4, 5};  // 编译错误！
```

### 栈溢出风险
**内存分配在栈上**：VLA在程序运行时分配数组空间大小，其位于内存的栈区域（类似于函数内的临时变量），如果数组太大可能导致栈溢出。

```c
int n = 1000000;  // 非常大的数  
int huge_arr[n];  // 危险！可能导致栈溢出
```

### 兼容性问题（程序可移植性）
不是所有的编译器都支持 C99 标准里面的VLA特性，并且可能需要特定的编译器标志位来启用。
比如：C++ 标准不支持变长数组（虽然有些C++编译器作为扩展支持）。
VLA特性在 C11 标准里面已经被进行标记，可能会在未来的 C 语言标准中移除，因此需要注意代码的可移植性。

# 应用
说实话，变长数组在实际项目中使用频率并不算特别高，主要原因有：
**（1）内存安全考虑**：由于是在栈上分配内存，大小不可控的数组可能导致栈溢出
 **（2）兼容性问题**：一些嵌入式系统或老旧编译器可能不支持 C99 标准
**（3）动态内存分配的替代方案**：对于真正需要动态大小的数组，许多程序员更习惯使用`malloc/free`
```c
// 使用malloc的替代方案  
int *arr = (int *)malloc(size * sizeof(int));  
if(arr != NULL) {  
    // 使用arr  
    free(arr);  // 使用完记得释放内存  
}
```

# 变长数组 vs 动态内存分配
什么时候用变长数组，什么时候用 malloc 呢？这里有个简单指南：
- **使用变长数组**：当数组大小适中（几MB以内），且只在当前函数内短暂使用。
- **使用malloc**：当数组较大，或需要长期存在，或需要在函数间传递。

## 零长度数组
`GNU C` 可能觉得变长数组还不过瘾，再来一个实锤：`支持零长度数组`。这下没有其它编译器比我狠吧！
是的，如果我们在程序中定义一个零长度数组，你会发现除了 GCC 编译器，在其它编译环境下可能就编译通不过或者有警告信息。零长度数组的定义如下：
```c
int a[0];
```

### 特性
#### 零长度数组不占用内存空间
零长度数组有一个奇特的地方，就是它不占用内存存储空间。我们使用 sizeof 关键字来查看一下零长度数组在内存中所占存储空间的大小，代码如下。
```c
int buffer[0];  
int main(void)  
{  
    printf("%d\n", sizeof(buffer));  
    return 0;  
}
```
在这个程序中，我们定义一个零长度数组，使用 sizeof 查看其大小可以看到：零长度数组在内存中不占用空间，大小为0。

### 应用
零长度数组一般单独使用的机会很少，**它常常作为结构体的最后一个成员，构成一个变长结构体**。
```c
struct buffer{  
    int len;  
    int a[0];  
};  
int main(void)  
{  
      printf("%d\n", sizeof(struct buffer));  
      return 0;  
}
```
零长度数组在结构体中同样不占用存储空间，所以 buffer 结构体的大小为4。
