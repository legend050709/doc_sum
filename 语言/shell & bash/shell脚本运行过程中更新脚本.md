# 问题

工作中经常会遇到，在执行一个脚本时后，觉得有些地方要补充，而这个脚本又已经运行了一段时间，如果从头再来很浪费时间，这时如果能修改这个运行中的脚本就方便多了。

或者 

某个死循环持续运行的脚本进程，想要不重启脚本进程的情况下，更新脚本内容。


# 注意

区分原始文件的修改 和  原始文件删除后创建了同名的新文件 这样的不同的场景。
这两种情况是不同的，前者文件的 inode 没有发生变化，后者文件的 inode 已经发生了变化。

```bash
ls -al -i xxx
查看文件的 inode
```

## python解释器的读取机制

python不会因为脚本改变而发生功能变化，是因为python会一次性把所有的东西都翻译成字节码再开始执行。


如果是python脚本程序在运行过程中，更新 python 脚本（注意是更新脚本，inode不变，不是删除再添加同名的文件），则原始的python 脚本的执行 结果不受到影响，即还是按照老的脚本内容进行执行。


### python 解释器和 bash 解释器的区别


说python是先编译再执行，有一个直接的证据就是你在python里写代码，第六行出现了一个缩进错误，那么前1到5行的代码都不会被执行的。但如果是在bash里，你第六行出了个语法错误，那么1到5行的东西仍然会被正确的执行。

### 恢复进程不存在的误删除文件

文件被删除后，此时如果没有守护进行或者后台进程对其持续输入，所以删除就真的删除了。`lsof`也看不到，故需要采用工具进行恢复。

#### 流程方法

采用的工具是extundelete第三方工具。恢复步骤以及注意事项如下：

- （1）停止对当前分区做任何操作，防止inode被覆盖。
> 通过umount命令，对当前设备分区卸载。`umount /dev/vdb1`

- （2）通过dd命令对 当前分区进行备份，防止第三方软件恢复失败导致数据丢失。
> 如备份可以考虑如下方式：`dd if=/path/filename of=/dev/vdc1`


- (3）下载第三方工具extundelete安装
```bash
wget  http://nchc.dl.sourceforge.net/project/extundelete/extundelete/0.2.4/extundelete-0.2.4.tar.bz2
tar jxvf extundelete-0.2.4.tar.bz2
cd  extundelete-0.2.4

make  install
```

### 解决
#### 需求

如果某个 Shell 脚本文件，可能存在变更，则变更的方式是**通过覆盖（即删除，然后再拉取新的文件）**；期望 该脚本文件，在变更之后，原始的脚本进程，已最新的脚本内容进行执行。

比如 可能存在变更的脚本文件为：exec_file.sh 「该文件内部为死循环一直执行」,  正常情况下 是 通过  sh exec_file.sh 来执行该文件。后续可能 exec_file.sh  存在变更，又期望 不停止原有进程的情况下继续执行新的脚本内容。

#### 解决方法

将执行的脚本文件，再封装一层，最外层的脚本始终不会变动。
即 封装一个新的脚本文件： new_exec_file.sh , 通过 sh  new_exec_file.sh 来启动脚本进程。
new_exec_file.sh 永远不会变更，后续变更只需要变更 exec_file.sh 文件即可。那么新的变更就可以在 原有进程中生效。

```bash
# cat new_exec_file.sh
#!/usr/bin/env bash
sh exec_file.sh
```
