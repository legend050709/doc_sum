# 问题
配置：
```text
主机一配置：eth0：1.1.1.1/32
主机二配置：eth0：2.2.2.2/32
主机一和主机二的eth0用一根网线直连。

主机2.2.2.2上的配置：
	ip route add 1.1.1.1/32 via 1.1.1.1 dev eth0 onlink
	sysctl -w net.ipv4.conf.eth0.rp_filter=0
主机1.1.1.1的配置：
	ip route add 2.2.2.2/32 via 2.2.2.2 dev eth0 onlink
	sysctl -w net.ipv4.conf.eth0.rp_filter=0
```

问题是：
    在两台主机都不添加任何新的IP地址的前提下，主机一和主机二可以相互ping通吗？
# 结果
即便直连的两台机器配置的IP地址不属于同一网段，也可以相互ping通，关键是要有路由！
# 解析
## onlink路由
onlink路由是可以直接arp目标地址的，而不是arp下一跳地址。
可以理解为路由是直连路由。
意思就是说，目标地址是属于跟本地直连的二层链路上，不跨三层。既然是不跨三层的链路，arp就可以畅行无阻，而标准中又没有规定arp协议包的请求源和请求目标必须是同一个网段的地址(甚至都没有掩码约束)。
所以说，一个以下的arp请求是有效的：
**源地址1.1.1.1请问，地址为2.2.2.2的网卡的MAC地址是多少？**

## rp_filter
好了，arp已经可以发出了，问题是当2.2.2.2网卡收到arp之后，该如何反应呢？

地址为2.2.2.2的网卡收到arp请求之后，会执行arp处理。由于arp是广播发送，因此只要不跨三层的链路上所有的主机都能收到这个arp请求，所以每一个主机首先它会检查这个arp是不是发给自己的，检查的办法很简单，就是执行一次路由查找！

路由查找的目标IP就是arp的目标IP，如果路由查找结果的路由项属性是本地地址，那么就说明请求的目标IP就是本机，这个arp请求就是发给自己的。到此为止，好像问题没有了，收到的arp请求的是本机IP地址，照理说本机理应回应一个arp repy了。是这样吗？
因为默认Linux针对每个网卡启用了rp_filter选项，这个选项是使能的是反向路由查找，即针对收到数据包的源地址做路由查找，如果查找结果的出口网卡不是收到数据包的网卡的话，查找将失败。
在本例中，由于主机2.2.2.2已经配置了到达1.1.1.1的onlink路由，所以说查找是成功的。

# 总结
IPv4 网络是否连通和物理网络的结构没有关系，只和路由有关，只要有路由就能通就可以联通。
> 注：对于IPv6网络，可能还有scope的要去。比如 link-local 地址不能用于通信等。全局唯一地址用于全局，站点唯一地址只能用在站点。
