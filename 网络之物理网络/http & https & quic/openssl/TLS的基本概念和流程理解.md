# HTTPS证书的验证过程
## 简化的流程
1.客户端向服务端请求证书（server.crt）
2.服务端下发证书（server.crt）
3.客户端用预制的受信任机构的证书（ca.crt）来验证服务端下发的证书（server.crt）是否合法，并且还会校验下发下来的证书里的域名与要请求的域名是否一致。
【以下步骤开启双向验证后才会触发】
4. 客户端选择一个由受信任的机构（ca.crt）颁发的证书（client.crt）发送给服务端
5.服务端用预制的受信任机构的证书（ca.crt）来验证客户端传来的证书（client.crt）是否合法。


## 浏览器通过HTTPS访问网站的流程
通过 HTTPS 访问网站时，浏览器和服务器之间的通信过程涉及多个步骤和技术细节。以下是完整的流程，以及浏览器如何获取和验证证书，确保 HTTPS 通信的安全性。

### 完整流程

**（1）DNS 查询**:
- 用户在浏览器中输入 URL（如 `https://www.example.com`）。
- 浏览器通过 DNS 查询将域名解析为 IP 地址。

**（2）建立 TCP 连接**:
- 浏览器与服务器之间建立 TCP 连接，通常使用三次握手（SYN, SYN-ACK, ACK）来完成。

**（3）TLS 握手**:
- **客户端 Hello**: 浏览器（客户端）发送一个 "Client Hello" 消息，包含支持的 TLS 版本、加密算法、随机数等信息。
- **服务器 Hello**: 服务器响应 "Server Hello" 消息，选择 TLS 版本、加密算法，并发送其数字证书。
    
**（4）证书获取**:
- 服务器向浏览器发送其 SSL/TLS 证书，该证书包含服务器的公钥、证书颁发机构（CA）的签名、有效期等信息。
- 浏览器会从服务器接收到的证书中提取 `commonName` 和 `Subject Alternative Name`（SAN）用于后续验证。

**（5）证书验证**:
- **(5.1)有效性检查**:
	- 有效期: 检查证书是否在有效期内。
	- 撤销检查: 使用证书撤销列表（CRL）或在线证书状态协议（OCSP）检查证书是否被撤销。
- **(5.2)信任链验证**:
	- 浏览器检查证书是否由受信任的 CA 颁发，验证证书链，确保从服务器证书到根证书的每个证书都是有效的。
- **(5.3)域名匹配**: 浏览器检查访问的 URL 是否与证书中的 `commonName` 或 SAN 匹配。

**(6) 会话密钥交换**:
- 如果证书验证通过，浏览器生成一个随机的会话密钥（Pre-Master Secret），并用服务器的公钥加密这个密钥，然后发送给服务器。
- 服务器使用其私钥解密该会话密钥。

**(7) 建立加密通道**:
- 双方使用会话密钥生成对称密钥，用于后续的加密通信。
- 客户端和服务器交换 "Finished" 消息，表明握手成功，接下来的数据将使用加密通道进行传输。

**(8) 数据传输**:
- 浏览器和服务器之间的所有数据都通过加密的 TLS 通道进行安全传输。

**(9) 连接关闭**:
- 当会话结束时，客户端和服务器可以通过发送关闭通知来安全地关闭连接。

### 浏览器内签的组件
为了保证 HTTPS 通信的正常，浏览器内嵌了以下几个关键组件：

- **CA根证书列表**: 浏览器内置的受信任的CA根证书列表(ca.crt list )，确保只有由这些 CA 颁发的证书才能被信任。
- **加密库(TLS库)**: 用于实现 TLS 协议的加密算法和功能，处理数据的加密和解密。
- **撤销检查机制**: 支持 CRL 和 OCSP，确保可以实时检查证书的有效性。
- **安全警告系统**: 当证书不匹配、无效或过期时，浏览器会发出警告，提醒用户注意。
